## How a flag is classified

Each consonant error the app's kept grade records for a false flag (another consonant, a target or soft pair, a collapsed geminate) is placed on Muraja's reference for its ayah (`quran.db`: the phonetizer over the whole ayah, wasl inside, waqf at its end) at the group the word scorer numbers, and read in order:

1. **reference, the phonetizer:** the mushaf's marks say the letter is not pronounced as itself there (a silent letter, a hamzat al-wasl inside the ayah, an unmarked letter before a shaddah, an unmarked noon, an unmarked meem before baa, a tanween marked as not izhar or for iqlab) and the phonetizer kept it;
2. **reference, Muraja's word scorer:** what was recited is known (QUD, Tadabur: the item's realized reference, its last word in waqf) and does not hold the letter there;
3. **unclear:** what was recited is not known (device sessions) and the letter drops if the reader paused on the word, started at it, or joined it across an ayah boundary;
4. otherwise Hafs pronounces the letter. What the engine heard decides: the query of the check that set the kept grade (QUD, Tadabur: the checks whose own grade of the word is the kept one; a device session keeps no per-check grade, so every check whose query can hold the letter). A query is the last 20 confirmed Characters, the pending hops and the check's overlap; which hops were pending is not recorded, so every count up to Muraja's 7 is a possible query, and one whose alignment does not reach the letter is set aside. **Grading** (Muraja's word scorer) where every possible query holds the letter there; **model** where none does; **unclear** where they disagree or none reaches it. The owner's sessions have no decode in the repo: the owner's verdict stands in where the phone showed the word.

A flag whose letter is not in the word, or whose candidate letters (no group kept) are classified differently, is **unclear**. Idgham, iqlab, lam shamsiyyah and the madd and hamzat al-wasl dropped in wasl are already applied in Muraja's reference (`مِّن لَّدُنۡهُ` is `ممممِ للَدُنهُ`, `بَل رَّفَعَهُ` is `بَ ررَفَعَهُ`), so a flag on them names the letter the reference holds, not the one the spelling shows.

**What this does not check:** where an assimilated letter goes, or that the letters the reference keeps are the right ones. A reference that wrote a wrong letter in place of a pronounced one (a planted `ن` for 4:158's geminate `ر`) passes it. It is no claim that the reference equals Hafs; the flags rest on the spelling check below.

## What this can and cannot say

- **Can:** for each consonant false flag in these populations, whether the realized reference holds the expected letter there, how the mushaf spells and marks it, and whether the queries that can have set the kept grade hold it.
- **Cannot:** whether a professional reciter actually pronounced every letter (the QUD recitation is presumed correct, nobody listened); which hops a check still held pending (a class holds only where every possible query agrees); a device session's pauses and the check that set its kept grade. A query is read by the truth-site scorer's carrier rule, so one that holds the letter next to an inserted one, or one half of a geminate the scorer split, can read as holding it (the grading list is for the owner to check).
- QUD's intervals are clustered by mushaf and surah (two reciters: they describe these recordings, not reciters); the device logs' by log; the owner's sessions, the word sample and the held-out verified sites (selected at target-pair swaps, so their rates are not population rates) carry counts and points only.
