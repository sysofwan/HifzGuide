## 2. Per-window logit length + 16 GB fit

The post-adapter 40 ms logit length is `muaalem_lattice_length(feature_frames)` (the single stride-2 adapter conv); the deployed 250-frame window yields 125 logit frames. ADR-0004's `target_len < frames` preflight is checked against this 40 ms length, not the 20 ms feature count.

| window | feat frames (20 ms) | logit frames (40 ms) | whole-clip coverage | waqf-seg coverage | max micro-batch @15 GB |
|---|---|---|---|---|---|
| 3 s | 150 | 75 | 3% | 5% | 741 |
| 5 s **(deployed)** | 250 | 125 | 16% | 25% | 404 |
| 8 s | 400 | 200 | 36% | 58% | 222 |
| 10 s | 500 | 250 | 49% | 74% | 164 |
| 20 s | 1000 | 500 | 85% | 99% | 60 |
| 40 s | 2000 | 1000 | 99% | 100% | 19 |

Per-window estimate at the 5 s window (bf16): frozen backbone 1.1 GB + fixed overhead 1.5 GB + 0.03 GB activations per window with per-layer activation checkpointing (0.46 GB without). Activation memory grows ~quadratically with window length (the attention-score buffer), so a whole-clip window OOMs without checkpointing; but at the fixed 5 s window memory is comfortable either way. The window length is therefore pinned by the ANE fixed-shape inference contract, not by the training memory budget.

Budget: 16 GB physical (RTX 5060 Ti), ~15 GB usable. These are **estimates** from the activation-recomputation formula (Korthikanti et al. 2022) with a Conformer factor; ADR-0004 still requires verifying one real batch fits before committing.

## 3. Candidate windowing policies (edge ownership + stitch)

### non-overlapping tiling (current provisional default)

- **Window / overlap**: 5 s window, 0 s overlap (5 s hop, 1.00x window passes).
- **Edge ownership**: A window owns exactly the audio in its [start, start+5s) span. A waqf pause or word straddling a tile boundary is split: its onset falls in the earlier window and its tail in the later one, and neither sees the whole pause. The boundary event is attributed to the window containing the frame where silence crosses the threshold (the earlier window for a pause that starts before the seam). Matches training.waqf_distill.WindowContract's default (hop == window).
- **Stitch**: Concatenate each window's 40 ms silence frames end-to-end in window order; student frame counts sum exactly to the clip lattice length because tiles do not overlap. Zero reconciliation, but a pause or qalqala closure sitting on a seam is seen half in each window and can be missed or double-counted.
- **Trade-off**: Cheapest (one window pass per 5 s of audio) and already implemented, but the seam is a blind spot exactly where waqf detection matters.

### center-trusted overlap

- **Window / overlap**: 5 s window, 1 s overlap (4 s hop, 1.25x window passes).
- **Edge ownership**: Windows step by a 4 s hop with 1 s overlap, so every clip position (except the outermost 0.5 s) is interior to at least one window. The overlap region is owned by the window whose center is nearer the frame — each window is authoritative only over its central [0.5s, 4.5s) band, discarding its outer 0.5 s. A 1 s overlap exceeds the 700 ms waqf post-processing window plus a short word, so no interior stop is ever trapped in a discarded edge.
- **Stitch**: For each 40 ms frame keep the silence posterior from the window that owns it (nearer center); no averaging, so a boundary is graded by the window that saw it in full context. Requires the frozen hop/overlap and the 2:1 pooling to be applied identically in train, eval, and export (ADR-0004).
- **Trade-off**: ~1.25x the window passes of a tiling (5 s / 4 s hop) — negligible at 5 s windows, where a micro-batch of dozens still fits 16 GB — in exchange for no seam blind spot. The overlap size is the one free parameter A2 must set.

## 4. Recommendation for A2

Keep the deployed **5 s** window (250 feature frames -> 125 frames on the 40 ms lattice). It is **fixed by the ANE**, which requires a static input shape (`ml-model-transformation.md`), so training must match inference regardless of what the duration data alone might suggest. Training memory is **not** the binding constraint at this length: an estimated micro-batch of 404 windows fits 15 GB usable under bf16 + activation checkpointing, and grad-accumulation recovers any effective batch. Because ~84% of whole recitations and ~75% of waqf segments exceed one window, multi-window stitching is the **norm**, so the real decision A2 owns is the **overlap / edge-ownership / stitch policy, not the window length**. Provisional recommendation: move from the current non-overlapping tiling to the **center-trusted 1 s overlap**, so no interior waqf lands on a seam blind spot; the exact overlap is A2's to freeze. The current code default (`training.waqf_distill.WindowContract`, hop == window) stays valid until then. A **provisional cap** of ~40 s (~99th percentile of whole clips, 2000 feature frames, ~8 windows) bounds the per-clip window count and the longest CTC target A2/#25 must preflight; clips beyond it are flagged for A2 rather than silently truncated.
